# Spec: the factory view in `ccmon-tui`

A fourth view shows what the factory is doing, per repository: every task with its phase, and the number in motion against the cap. The cap is editable there. Look and feel follow `docs/specs/tui.md`.

## Facts this depends on
Read in `factory/bin/factory` on main after PR #7 (line numbers at 69e1205), and measured on this machine 2026-11-14.
- `factory status --json` (`cmd_status`, line 484) prints one object: `rows` (list), `cap`, `open`, `in_motion`, `in_review`, `merged`, `leftover_agent_worktrees`, `outside_worktrees` (integers).
- Each row (`collect`, line 217): `slug`, `branch` (string or null when detached), `path`, `session_id` (string or null), `session` (a session state such as `working`, `done`, or `none`, `unknown`), `blocked` (string or null), `base` (recorded `factoryBase`, else the default branch as `origin/main`), `elapsed` (integer seconds since the session started, or null), `overtime` (bool), `dirty` (bool or null), `behind`, `ahead` (integer or null), `head`, `last_commit` (unix seconds or null), `pr_state` (`open`, `closed`, `merged`, `none`, `unknown`), `pr_url`, `pr_head`, `pr_base` (strings, empty when absent), `phase` (`motion`, `review`, `merged`), `stale` (bool).
- It takes the repository from the working directory. Outside a git repository it prints `factory: not inside a git repository` on stderr and exits 2. A settings file that is not a JSON object, or an invalid value, is also exit 2 with one line on stderr (`load_settings`, line 59).
- Cost per run: one `git worktree list`, one `git symbolic-ref`, one `claude agents --json --all`, and per task four `git` calls and one `gh pr list` (the only network call). No call has a timeout. Measured here with 7 tasks, three runs: 3.5 to 4.3 s wall (38 subprocesses), about 0.5 s of it per `gh` call; 0.5 s in total without `gh`.
- `gh` missing or failing: the row gets `pr_state: unknown`, phase `motion`; the command still exits 0 with JSON. Run with `gh` off `PATH` (0.5 s) and with an unreachable host (0.8 s): exit 0, every row `unknown` and `motion`, so offline the view shows every task in motion rather than an error. Not run: a zero-task repository (from the code: `rows: []`, exit 0; the tests below run it) and a missing `claude` (from the code: `session: unknown`, phase `motion`, exit 0).
- Settings (`load_settings`): `~/.claude/factory/settings.json`, keys `worktree_cap` (default 5, an integer of at least 1, not a bool), `lead_model`, `lead_permission_mode`, `task_time_limit_hours`. A missing file means defaults. No environment variable moves the file.
- The `factory` script ships in this repository at `factory/bin/factory` (Python 3.11+, standard library only), next to the `ccmon/` package the dashboard already locates (`CCMON_ROOT`, else the executable's path).
- `sessions --json` carries `repo_path` per session: the main checkout, also for sessions that ran in a task worktree (`docs/specs/task-grouping.md`). On this machine the 7-day range holds 6 distinct paths; 3 of them have a `.claude/worktrees` directory.

## Decisions
- **The command:** `python3 <ccmon root>/factory/bin/factory status --json`, with the working directory set to the repository. Same root and interpreter as the ccmon CLI, so nothing new to install or configure, and the dashboard never runs a factory of another version. No environment override.
- **Which repositories:** the distinct `repo_path` of the sessions loaded for the current range, kept only when `<repo_path>/.claude/worktrees` is a directory (a stat; a repository that never had a worktree cannot have a task, and is not worth a Python process and a `claude agents` call each refresh). Ordered by name, then path. `r` therefore keeps its meaning in this view: a wider range can bring in more repositories.
- **Phases are never derived in Go.** The view renders `phase`, the counts and `cap` as `factory status` reports them. A phase value the view does not know (the declared states coming with `explicit-task-state`) renders as its own name in the muted colour and sorts after the known ones.
- **Cadence:** the view refreshes only while it is on screen: on entering it (unless a result younger than 5 s is held), then every 30 s counted from the end of the previous refresh, and right after the cap is saved. One refresh in flight at most; a refresh runs the repositories concurrently, each call under a 30 s timeout and the quit context, through the Runner so `Wait` covers it. While another view is shown, nothing runs. At 30 s a repository with 7 tasks makes 840 `gh` calls an hour while the view is watched, against GitHub's 5,000 an hour for an authenticated user; a refresh takes about 4 s, so 30 s between refreshes keeps the factory's processes under about an eighth of the time.
- **Editing the cap:** `c` in the factory view opens an inline number field prefilled with the value read from the settings file at that moment. Digits type (three at most), `backspace` erases, `↑`/`k` and `↓`/`j` add and subtract one (never below 1), `enter` saves, `esc` cancels. Valid is an integer from 1 to 999; `enter` on anything else keeps the field open and says why. While the field is open every other key is swallowed except `ctrl+c`.
- **Writing:** on save the file is read again, the `worktree_cap` key is set, and the object is written back with every other key's value byte-for-byte as it was (two-space indent, trailing newline; key order is not preserved). The write goes to a temporary file in the same directory and is renamed over the target, so a reader never sees half a file. `~/.claude/factory/` is created when missing; an existing file keeps its permission bits, a new one gets 0644. A file that exists and is not a JSON object is never overwritten: opening the field, or saving, reports it by path and writes nothing. Nothing is cached: the cap on screen comes from the last refresh, the field from a fresh read, the write from a fresh read.
- **Known limit:** another writer that changes the file between the read and the rename of one save (a few milliseconds) loses its change.

## Data (`internal/data/factory.go`, new)
- `FactoryStatus` and `FactoryTask` decode the JSON above (only the fields the view uses: `slug`, `phase`, `base`, `elapsed`, `overtime`, `stale`, `pr_state`, `pr_url`, `session`; and the top-level counts and `cap`). Nullable numbers are pointers.
- `(*Runner).FactoryStatus(ctx, repoPath) (*FactoryStatus, error)`: runs the command above under `begin`/`calls` like `run`, with the timeout. Errors are one line: the last stderr line with the `factory: ` prefix removed, `factory status timed out after 30s`, `factory command not found: <path>` when the script is missing (checked with a stat before starting Python), or the decode error.
- `FactorySettingsPath()` (`~/.claude/factory/settings.json` from `os.UserHomeDir`), `ReadWorktreeCap(path) (cap int, err error)` (missing file or missing key: 5; not an object, or a value the factory would refuse: an error naming the path or key) and `WriteWorktreeCap(path, cap) error` as described under Writing. 5 is the factory's default, repeated here because the empty state shows it; the comment says where it comes from.

## View (`internal/tui/view_factory.go`, `internal/tui/factory.go`, new)
State, messages, the refresh command, the key handling of the cap field and the rendering live in these two files. Shared files change only to register: the `viewFactory` id, key bindings, the tab, the footer and help entries, one `case` in `frame`, `subheader`, `Update` (the message and the tick check), `handleKey`, `switchView`, `listLen`/scroll, `Snapshot` and `main.go`'s list of snapshot views.

- **Key and tab:** `4`, tab label `4 Factory` (the same at every width; if the header cannot hold four tabs and the range chips at 60 columns, the existing right-hand candidates drop first). `tab`/`shift+tab` cycle four views; with no session selected they skip the session view instead of stopping at it, so the factory view is reachable by `tab` on a machine with no sessions.
- **Subheader:** `Factory` then the totals over all repositories: `N in motion · N waiting for review · N merged, not cleaned`, then `as of HH:MM:SS`, or a spinner with `refreshing` while a refresh is in flight. Toasts as elsewhere.
- **Settings line** (top of the body): `worktree cap` and its value, `per repo`, the hint `c edit`, and at the right the settings path with the home directory shown as `~`. While editing, the value becomes the field (`[ 12█ ]`) and the hint `enter save · esc cancel · ↑↓ adjust`. The value is the `cap` reported by the last refresh; before any repository has reported, the value read from the file. When the file cannot be used, the line shows the error in red instead of a number.
- **One section per repository:** a header line with the name in bold, and at the right the capacity meter and the other two counts (`review N`, `merged N`). Under it a table, one row per task: `SLUG`, `PHASE`, `ELAPSED`, `PR`, `BASE`, `FLAGS`.
  - **Capacity meter:** `in motion`, then one cell per slot of the cap: filled for a task in motion, hollow for a free slot, then `M/CAP`. Filled cells are green below the cap, yellow at it, red above it; tasks beyond the cap add red cells past the last slot. With a cap above 20 the cells give way to a 20-cell proportional bar. In no-colour mode filled and hollow use different glyphs, so the meter reads without colour.
  - **Phase:** a glyph and a label, coloured: `motion` → `in motion` (blue, the glyph animates as a spinner while the task's `session` is `working`, static otherwise), `review` → `waiting for review` (yellow), `merged` → `merged, not cleaned` (green, muted). Shorter labels (`motion`, `review`, `merged`) below 100 columns.
  - **Elapsed:** `FmtDuration` of `elapsed`; `-` when null. It is the value from the last refresh, not ticked locally.
  - **PR:** `#N` (the last path segment of `pr_url`) followed by the state when it adds something the phase does not say (`open` on a task in motion, `closed`); `-` for `none`; `?` for `unknown`.
  - **Base:** a stacked task (its base is a `worktree-<slug>` branch) shows `↳ <slug>` in purple; otherwise the base with a leading `origin/` removed, faint.
  - **Flags:** pills: `overtime` red, `stale` yellow.
  - Rows are ordered by phase (motion, review, merged, then unknown values by name), overtime first inside a phase, then slug.
  - Columns drop below the width that holds them in this order: `BASE` first, then `PR`, then `ELAPSED`; `SLUG`, `PHASE` and `FLAGS` always show. Slugs truncate by display width.
  - A repository whose status call failed shows its header and the one-line error in red in place of the table. A repository with no task shows `no tasks` (faint) and an empty meter.
- **Empty state** (no repository qualifies): centred, not an error: `No factory tasks here yet`, one muted line saying tasks appear when a dispatcher starts leads with `/factory:dispatch` in a repository seen in this range, and the settings line stays above it so the cap is still editable. Before the first result arrives: a spinner with `asking the factory…`.
- **Scrolling:** the body is a list of lines; `j`/`k`, arrows, `g`/`G`, page keys scroll it when it is taller than the window, and a faint `+N more lines · ↓ to scroll` replaces the last line when cut. No row selection (nothing acts on a task yet; `explicit-task-state` adds the cursor with its acknowledge key).
- **Footer:** `↑↓/jk move`, `c edit cap`, `r range`, `tab next view`, `? help`, `q quit`; while editing: `enter save`, `esc cancel`. Help overlay: `4` joins the view keys (`1 2 3 4`, `dashboard · session · agents · factory`), `c` gets a line, and one faint sentence says the factory view refreshes every 30 s while shown.
- **Motion:** only the spinner of working tasks and of a refresh in flight, on the existing tick (`animating` is true in this view while either shows). Static mode renders frame 0.
- **Room for what comes next** (not built): a "needs you" section is another block above the repository sections; cost per task is another column before `FLAGS`. Neither needs a change to what is built here.

## Tests
- Data: `FactoryStatus` against a stub script (the fixture JSON decodes with nulls; exit 2 gives the stderr line without the prefix; a hang times out and frees the Runner; a missing script names the path; after `Wait` no process starts). `ReadWorktreeCap`: missing file, missing key, valid, each invalid value (0, -1, 1.5, `true`, a string), not an object, not JSON. `WriteWorktreeCap`: creates the directory and file; preserves other keys' values exactly (a nested object, a float written as `2.0`); keeps the file mode; refuses a non-object and leaves the bytes untouched; leaves no temporary file behind.
- One real run: `FactoryStatus` against the real `factory/bin/factory` in a temporary git repository with no tasks (skipped when `git` or `python3` is missing) returns zero rows and the default cap with `HOME` pointed at an empty directory.
- Update loop with the stub: entering the view starts exactly one refresh; a tick before 30 s starts none, after 30 s one; none while another view is shown; a second entry within 5 s starts none; a result for a repository list that has since changed is still applied whole (no stale merge logic); saving the cap writes the file and starts a refresh; one refresh in flight at most.
- Cap field: `c`, digits, backspace, arrows at the lower bound, `enter` with an empty field or `0` keeps it open with a message, `esc` leaves the file untouched, other keys (`q`, `tab`, `4`) do nothing while it is open, a non-object file refuses to open it.
- Rendering: the factory view joins `TestRenderAllViewsAllSizes` and the empty-state test (exact height, no over-wide line, no-colour without escapes), in each of: several repositories with every phase, overtime, stale, stacked, a failed repository, over the cap, cap above 20, an unknown phase, editing.
- `tab` cycles four views and skips the session view without a selection.
- Golden snapshots from a fixed fake status at 140x40, 100x30 and 80x24 (no-colour), plus the empty state at 80x24; the help goldens change.
- Screenshots (colour) at 140x40, 100x30 and 80x24, of the fake status and of this machine's real factory, looked at by the coder, the reviewer and the lead. The test that writes the goldens also writes the coloured frames to `$CCMON_SHOT_DIR` when that is set, which is how the fake status reaches `tools/ansi2html.py`.

## Out of scope
Anything under `factory/`; acting on a task (open, acknowledge, dismiss); cost per task; the other settings keys; the kaizen stats page.
